Add stall recovery and disable the runtime gamepad poller

The core still freezes two to three seconds after the game starts, with
no input from the plugin: the telemetry shows simCalls=0, the frame
counter stops at 66-83, the CPU goes idle and the WebAssembly trap
("call_indirect to a signature that does not match") is raised from
inside the core module, reached through the frame callback.

Ruled out so far, all checked on the device:
- The core file is not corrupt: the one on the phone and the one from
  cdn.emulatorjs.org have the same md5 (912b0244ac4543ecb2e9e37edf6a8281).
- The button ids are in range: the core declares 0,2,3,4,5,6,7,8,10,11
  and the plugin only sends those.
- The plugin is not the sender: simCalls is 0 in the freezing session.

Changes:
- Override navigator.getGamepads() to report no device. The runtime
  polls it every 10 ms and on this WebKit build it may report a ghost
  gamepad whose 16 buttons include ids the core does not declare; those
  would be pushed into the core input callback and trap the module.
- Show a recovery panel when the frame counter has not moved for five
  seconds: "重进" reloads the plugin page and re-enters the same game,
  restoring the autosave, and "旧版核心重进" does the same with the
  non-WebGL2 core build for comparison.
- Remember the running game in localStorage so the recovery can re-enter
  it automatically; an intentional exit clears the marker.

Verified on the device: the extracted script block passes node --check,
the 20 unit tests pass with the 12 device-dependent ones skipped, and
the plugin telemetry now reports the core button table, the trap origin
and the stall state. Whether the freeze is gone still needs a run on the
device.
